# scenarios/

Run configurations for `scripts/run_simulation.py` (`simulation/`) and
`scripts/run_AIS.py` (`real/`). Both scripts take `--config <path>`, so a copied
config can live anywhere. See the [main README](../README.md) for how to run and
edit them.

```
simulation/          synthetic scenarios, no data needed
simulation/milliampere/  the same, scaled by 0.3 with ego on the milliAmpere model,
                     DP-following its own prediction
                     (generated by scripts/tools/scale_scenarios.py)
real/                window_054, window_079, window_098: the paper's AIS test windows
viz_reference.yaml   every plotting option with its default (reference only, not loaded)
```

## Config blocks

| Block | Used by | Controls |
|---|---|---|
| `scenario:` | run_simulation | time step, duration and the vessels: start position, speed, intent, motion model (`sim_model`), policy and VO parameters; optional `classifier:` overrides the COLREGs classifier's distances |
| `data:` | run_AIS | which encounter window to play (`pkl_path`, `window_id`), frame range, vessels to exclude |
| `prediction:` | both | prediction horizon, responding filter, number of hypotheses drawn; in run_AIS also the nominal layer (`prediction.nominal`) and the VO parameters (`prediction.interaction.agent`) |
| `metrics:` | run_AIS | ADE/FDE scoring against the ground-truth AIS (`--metrics`) |
| `viz:` | both | plotting only; it does not change the predictions |

Unknown keys under `prediction:` and in the VO parameters raise an error, so
typos are caught.

## Model mismatch

By default a target runs the same decision rule and parameters the
predictor assumes for it, so a compliant target is predicted almost exactly.
To test against vessels that behave differently from the model:

* **A different decision rule:** set the target's `policy` to `vo_kuwata`
  (COLREGs-aware grid search) or `cto` (collision avoidance without COLREGs,
  needs `sim_model: ct_decoupled`). The predictor keeps `prediction.policy_type`.
* **Different parameters:** a vessel's `actual:` block holds VO parameters the
  simulated vessel really uses; the predictor keeps the values set on the
  vessel itself.

  ```yaml
  target_1:
    d_pass: 75.0          # what the predictor assumes
    actual:
      d_pass: 45.0        # what the vessel really keeps
      tcpa_threshold: 30.0
  ```

* **Random parameters:** `scenario.mismatch` draws each target's `actual`
  values (ego is left alone) as its configured value times a uniform factor
  in [1 - r, 1 + r]. Values set in `actual` are kept.

  ```yaml
  scenario:
    mismatch:
      seed: 1
      jitter: {d_pass: 0.4, tcpa_threshold: 0.4, los_lookahead: 0.4}
  ```

`run_simulation.py` prints each vessel's `actual` values at startup.

## Adding a real-data window

1. Find a `window_id` with `python scripts/tools/browse_encounters.py` (or
   `python scripts/run_AIS.py --list`), and note the MMSIs of vessels that are not
   part of the encounter.
2. Copy `real/window_098.yaml` and set `data.window_id` and `data.exclude_mmsi`.
3. Run it once without `viz.xlim`/`viz.ylim` (or with `viz.zoom_radius_m`) to see
   the extent, then set `xlim`/`ylim` to frame the encounter.
